# The design evaluation (Phase 1 of the PhD): code, licence and algorithm of each of the 45 designs

Run from the workspace root with `design-evaluation/.venv/bin/python`, in this order: `setup_designs.py`, `scan_paper.py`, `search_code.py` (all designs, one by one), `review_candidates.py <id>` and the verdicts in `code_verdicts.py`, `check_licence.py <id>` for accepted code, `algorithm_triage.py`, `reader_packets.py <id>` and the reader, `verify_reader_quotes.py <id>`, then `status.py` for the READMEs. Every output sits in `design-evaluation/designs/<id>/`.

| Script | Purpose | Usage |
|---|---|---|
| `algorithm_triage.py` | Counts, on the Mac and without showing any text, the signs that a design's paper describes its algorithm well enough to code it, and names the pages a reader should read. | `design-evaluation/.venv/bin/python scripts/design_eval/algorithm_triage.py [<id> ...]` |
| `check_licence.py` | Reads the licence of each repository the reviewer accepted as a design's code, says whether it lets us run and adapt the code, and clones it at a pinned commit when it does. | `design-evaluation/.venv/bin/python scripts/design_eval/check_licence.py <id> [<id> ...]` |
| `code_declarations.py` | Records, for each new design, whether its paper declares the code we hold, and writes the summary table design-evaluation/new-designs/CODE-DECLARATIONS.md. | `design-evaluation/.venv/bin/python scripts/design_eval/code_declarations.py` |
| `code_verdicts.py` | The reviewer's judgement on each design's code, kept in one place, written out as evidence/11-code-verdict.json in every design's folder. | `design-evaluation/.venv/bin/python scripts/design_eval/code_verdicts.py [<id> ...]` |
| `common.py` | Shared helpers of the design evaluation: the list of the 45 designs, their folders, and recorded web requests. | `imported by the other scripts of scripts/design_eval/.` |
| `feasibility.py` | Lists the 45 designs with how feasible each is to execute or simulate in Phase 2, from the design-evaluation records alone. | `design-evaluation/.venv/bin/python scripts/design_eval/feasibility.py [--out <trial file>]` |
| `fetch_datasets.py` | Puts each runnable design's datasets into its datasets/ folder, from a catalogue of where each dataset comes from and on what terms, and lists what needs the author. | `design-evaluation/.venv/bin/python scripts/design_eval/fetch_datasets.py <id> [<id> ...]` |
| `file_new_papers.py` | Files the papers of the new designs from the author's downloads into each design's paper/ folder, carving a chapter out of a book where the download is a whole volume. | `design-evaluation/.venv/bin/python scripts/design_eval/file_new_papers.py` |
| `meeting_deck_17nov.py` | Builds the slides for the supervision meeting of 17 November 2026: the evaluation of the designs (carried forward and not), the Winter Conference poster, the progress tracker and the next phase, in the author's biweekly format. | `python3 scripts/design_eval/meeting_deck_17nov.py [deck.pptx]` |
| `new_designs.py` | Finds designs outside the review's corpus that publish their code under an open licence and fit the PhD (privacy-preserving learning for NG-IoT security), and records the evidence for each. | `design-evaluation/.venv/bin/python scripts/design_eval/new_designs.py` |
| `new_designs_report.py` | Writes the shortlist of new designs (outside the corpus) whose code is published and which use zero-knowledge proofs, with or without a blockchain, against the PhD's threats; clones the licensed code at a pinned commit. | `design-evaluation/.venv/bin/python scripts/design_eval/new_designs_report.py [--no-doc] [--out <trial file>]` |
| `new_designs_zk.py` | Finds designs outside the corpus that combine zero-knowledge proofs with a blockchain in privacy-preserving learning, publish their code, and defend against the PhD's threats. | `design-evaluation/.venv/bin/python scripts/design_eval/new_designs_zk.py` |
| `phase2_tables.py` | Writes the two tables of what goes forward to Phase 2: the designs not carried forward, grouped by the reason, and the six designs carried forward with their code. | `design-evaluation/.venv/bin/python scripts/design_eval/phase2_tables.py` |
| `reader_packets.py` | Writes, for each design that needs a reader, the packet that tells the reader which page files of the paper to read first. | `design-evaluation/.venv/bin/python scripts/design_eval/reader_packets.py <id> [<id> ...]` |
| `redo_arxiv.py` | Finds, through Semantic Scholar, the arXiv preprint of each design whose arXiv look-up arXiv refused (status 429) during the code search, and checks that preprint for code. | `design-evaluation/.venv/bin/python scripts/design_eval/redo_arxiv.py [<id> ...]   (all designs with a refused look-up)` |
| `report.py` | Writes the Phase 1 report of the design evaluation (Docs/DESIGN-EVALUATION-PHASE1-<date>.html) from the evidence files of the 45 design folders. | `design-evaluation/.venv/bin/python scripts/design_eval/report.py [--out <trial file>]` |
| `review_candidates.py` | Shows the reviewer, for one design, the candidate repositories that the search tied to the paper, with what is needed to judge each. | `design-evaluation/.venv/bin/python scripts/design_eval/review_candidates.py <id> [<id> ...]` |
| `scan_new_papers.py` | Says, for each new design's paper, whether the paper declares its own code on GitHub (or another host) and whether that is the repository we cloned, without showing any of the paper's text. | `design-evaluation/.venv/bin/python scripts/design_eval/scan_new_papers.py` |
| `scan_paper.py` | Finds, on the Mac and without showing any of the paper's text, every link and every code- or data-availability statement in a design's paper. | `design-evaluation/.venv/bin/python scripts/design_eval/scan_paper.py [<id> ...]   (all 45 when no id is given)` |
| `search_code.py` | Searches every public place where a design's code could be, or could once have been, and records each request and its answer. | `design-evaluation/.venv/bin/python scripts/design_eval/search_code.py [<id> ...]   (all 45 in order when no id is given)` |
| `setup_designs.py` | Creates one folder per design under design-evaluation/designs/, with its identity and what the evidence sheet records. | `python3 scripts/design_eval/setup_designs.py` |
| `status.py` | Writes the README of every design folder and the overview README of the design evaluation, from the evidence files alone. | `design-evaluation/.venv/bin/python scripts/design_eval/status.py` |
| `study_cards.py` | Builds one card per design for the Phase 2 study, all 54 designs on one frame: the six carried forward and the 48 not carried forward. | `python3 scripts/design_eval/study_cards.py` |
| `study_datasets.py` | Lists every dataset the 54 designs of the Phase 2 study use, under one name each, with its kind and the designs that use it. | `python3 scripts/design_eval/study_datasets.py` |
| `study_designs_doc.py` | Writes the author's document of the designs as drawn: for each of the six carried forward, our diagram of one round beside the paper's own design figures and algorithm boxes; for each of the 48 not carried forward, the paper's design figures and algorithms with a short record of the design. | `python3 scripts/design_eval/study_designs_doc.py [trial-output.html]` |
| `study_diagrams.py` | Draws the six carried-forward designs in one style, as sequence diagrams of one round: who takes part and who sends what to whom, so that the designs can be compared side by side. | `python3 scripts/design_eval/study_diagrams.py` |
| `study_figures.py` | Crops from each of the 54 designs' papers its design figures and algorithm boxes, with their captions, for the author's document of the designs' own diagrams. | `python3 scripts/design_eval/study_figures.py [<id> ...]` |
| `study_packets.py` | Writes the reader packets of the Phase 2 design study: for each of the eleven designs that need a reader, which page files, page images, code and records the reader may use. | `python3 scripts/design_eval/study_packets.py [<id> ...]` |
| `study_report.py` | Writes the report of the Phase 2 design study: the six designs compared, their datasets and credibility, their runs and set-ups as the baseline to follow, and the qualitative analysis of the 48 not carried forward. | `python3 scripts/design_eval/study_report.py [trial-output.html]` |
| `verify_reader_quotes.py` | Checks that every quotation a reader gave is on the page it names, and that the reader's verdict file is complete, printing counts only. | `design-evaluation/.venv/bin/python scripts/design_eval/verify_reader_quotes.py <id> [<id> ...]` |
| `verify_study_quotes.py` | Checks each study reader's output: the form of study/reader.json, the review's allowed values in its P1 to P3 classification, and every quotation found on its page of the paper. | `python3 scripts/design_eval/verify_study_quotes.py [<id> ...]` |

Generated by `scripts/paper_ppml/folder_readmes.py` from each script's header; edit the headers, not this file.
